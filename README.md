# dataset-nlftp

国土数値情報（nlftp.mlit.go.jp）の行政区域・将来推計人口・鉄道・駅別乗降客数・医療機関・学校・福祉施設・バス・洪水浸水想定区域・津波浸水想定・土砂災害警戒区域・土地利用・用途地域・通学区域の GIS データを DuckLake カタログ化したデータセット。

## データ出典

国土交通省「国土数値情報ダウンロードサイト」が公開する以下のデータを使用する。

行政区域データ（N03、令和7年版 / 世界測地系）から全国の都道府県・市区町村の境界ポリゴンを収録する。座標参照系は EPSG:4612（JGD2011）。

- 行政区域データ（N03-2025）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2025.html

将来推計人口は「1kmメッシュ別将来推計人口データ（R6国政局推計）」を使用する。推計値は総務省「令和2年国勢調査」と国立社会保障・人口問題研究所「日本の地域別将来推計人口（令和5年推計）」に基づき、2020〜2070年の5年ごとの値を収録する。メッシュポリゴンの座標参照系は EPSG:6668（JGD2011）。

- 1kmメッシュ別将来推計人口（R6国政局推計）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-mesh1000r6.html

鉄道データは「鉄道データ（N02、令和6年版）」を使用する。全国の鉄道路線・駅を収録する。座標参照系は EPSG:6668（JGD2011）。

- 鉄道データ（N02-2024）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2024.html

駅別乗降客数は「駅別乗降客数データ（S12、2024年度版）」を使用する。全国の鉄道駅について 2011〜2024年度の1日あたり乗降客数を収録する。原典は鉄道事業者の提供資料で、各社が独自に算出した数値のため統一的な基準に基づくものではない。座標参照系は EPSG:6668（JGD2011）。

- 駅別乗降客数データ（S12-2024）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-S12-2024.html

医療機関データは「医療機関データ（P04、第3.0版 / 令和2年）」を使用する。全国の病院・診療所・歯科診療所の位置・診療科目・病床数・開設者分類を収録する。座標参照系は EPSG:6668（JGD2011）。

- 医療機関データ（P04-v3.0）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-P04-v3_0.html

学校データは「学校データ（P29、第2.0版 / 令和3年）」を使用する。全国の小学校・中学校・高等学校・大学・幼稚園・特別支援学校等の位置・学校分類・管理者を収録する。座標参照系は EPSG:6668（JGD2011）。

- 学校データ（P29-v2.0）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-P29-v2_0.html

バスは「バス停留所データ（P11、第3.0版 / 令和4年度）」と「バスルートデータ（N07、令和4年度）」を使用する。全国のバス停留所の位置・事業者・系統と、バス路線の経路を収録する。座標参照系は EPSG:6668（JGD2011）。いずれも旧版（P11 第2.0版 / 平成22年度・N07 平成23年度）は使用許諾条件が非商用のため使わない。

- バス停留所データ（P11-v3.0）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-P11-v3_0.html
- バスルートデータ（N07-2022）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N07-2022.html

洪水浸水想定区域データは「洪水浸水想定区域データ（河川単位）（A31a、2025年度）」を使用する。全国の洪水予報河川・水位周知河川およびその他河川の浸水想定区域のうち、想定最大規模（L2）の浸水区域ポリゴンを収録する（計画規模・浸水継続時間・家屋倒壊等氾濫想定区域は収録しない）。座標参照系は EPSG:6668（JGD2011）。

- 洪水浸水想定区域データ（河川単位）（A31a-2025）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A31a-2025.html

津波浸水想定は「津波浸水想定（A40、第2.1版）」を使用する。津波防災地域づくり法に基づいて都道府県が設定した浸水想定を、浸水深の区分ごとのポリゴンとして収録する。座標参照系は EPSG:6668（JGD2011）。津波浸水想定データは原典資料を作成した都道府県ごとに使用許諾条件が異なるため、配布ページで「オープンデータとして利用可（商用利用可・再配信可）」とされた都道府県のみを収録する。整備年度は都道府県ごとに 2016〜2022年度と幅がある。

- 津波浸水想定（A40-v2.1）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A40-v2_1.html

土砂災害警戒区域は「土砂災害警戒区域（A33、2025年度版）」を使用する。土砂災害防止法第7条に基づいて都道府県が指定した土砂災害警戒区域（イエローゾーン）・土砂災害特別警戒区域（レッドゾーン）を、急傾斜地の崩壊・土石流・地滑りという現象の種類ごとの区域ポリゴンとして収録する。データ基準日は2025年8月1日。座標参照系は EPSG:6668（JGD2011）。土砂災害警戒区域データは原典資料を作成した都道府県ごとに使用許諾条件が異なるため、配布ページで「オープンデータとしての利用可（商用利用可・再配信可）」とされた都道府県のみを収録する。

- 土砂災害警戒区域（A33-2025）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A33-2025.html

土地利用は「都市地域土地利用細分メッシュデータ（L03-b-u、第3.1版 / 令和3年度）」を使用する。3次メッシュを 1/10 に細分した 100m 四方の区画ごとに、地形図と衛星画像の判読による土地利用種別を収録する。整備範囲は都市地域に限られ、令和3年度版は北海道と東北北部が対象外。座標参照系は EPSG:6668（JGD2011）。

- 都市地域土地利用細分メッシュデータ（L03-b-u 第3.1版）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-L03-b-u-v3_1.html

福祉施設データは「福祉施設データ（P14、第2.1版 / 令和3年度）」を使用する。全国の保護施設・老人福祉施設・障害者支援施設・身体障害者社会参加支援施設・児童福祉施設・母子父子福祉施設等の位置・分類（大／中／小）・管理者を収録する。全国版が無く都道府県別に配布されるため47都道府県分を統合する。座標参照系は EPSG:6668（JGD2011）。一部の都道府県・市区町村は利用規約と異なる利用条件が付されているため、利用時は提供元の利用制限を確認すること。

- 福祉施設データ（P14-v2.1）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-P14-v2_1.html

用途地域データは「用途地域データ（A29、第2.1版 / 令和元年度）」を使用する。都市計画法に基づく用途地域のポリゴンと、指定建ぺい率・容積率を収録する。座標参照系は EPSG:6668（JGD2011）。用途地域データは原典資料を作成した市区町村ごとに公開条件が異なるため、提供元が配布する「公開に関する利用条件」で「オープンデータ公開可」とされた市区町村のみを収録する。

- 用途地域データ（A29-v2.1）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A29-v2_1.html

通学区域は「小学校区データ（A27、2023年度）」と「中学校区データ（A32、2023年度）」を使用する。市区町村の教育委員会等が指定する公立小・中学校ごとの通学区域ポリゴンと、文部科学省の学校コード・学校名・所在地を収録する。座標参照系は EPSG:6668（JGD2011）。通学区域データは原典資料を作成した市区町村ごとに公開条件が異なるため、提供元が配布する「公開に関する利用条件」で利用条件が「オープンデータ公開」とされた市区町村のみを収録する。

- 小学校区データ（A27-2023）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A27-2023.html
- 中学校区データ（A32-2023）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A32-2023.html

政令指定都市の区から市へのコード対応には、デジタル庁「アドレス・ベース・レジストリ（市区町村マスタデータ）」を加工して利用する。

- アドレス・ベース・レジストリ: https://dataset.address-br.digital.go.jp/

## テーブル: prefecture

都道府県の行政区域境界ポリゴン。N03（令和7年）の行政区域データを都道府県単位で集約したもの。

- prefecture_code: 都道府県コード（2桁）
- prefecture_name: 都道府県名
- geometry: 境界ポリゴン（EPSG:4612 / JGD2011）

## テーブル: municipality

市区町村の行政区域境界ポリゴン。N03（令和7年）の行政区域データを市区町村単位で集約したもの。同一自治体の飛び地等は ST_Union_Agg で統合済み。政令指定都市は区単位で収録され、行政区名を ward_name に持つ。

- lg_code: 全国地方公共団体コード（5桁、都道府県2桁 + 市区町村3桁）
- prefecture_code: 都道府県コード（2桁）
- prefecture_name: 都道府県名
- county_name: 郡名
- city_name: 市区町村名
- ward_name: 行政区名（政令指定都市のみ。他は NULL）
- geometry: 境界ポリゴン（EPSG:4612 / JGD2011）

## テーブル: designated_city

市区町村境界（政令指定都市の区を市レベルに統合）。municipality モデルから政令指定都市の区を ST_Union_Agg で結合し、市単位の境界として出力する。区コードから市コードへのマッピングは、デジタル庁「アドレス・ベース・レジストリ（市区町村マスタデータ）」を加工して作成。東京23区（特別区）は独立した地方公共団体のため統合しない。

- lg_code: 全国地方公共団体コード（5桁、政令指定都市は市レベルのコード）
- prefecture_code: 都道府県コード
- prefecture_name: 都道府県名
- county_name: 郡名
- city_name: 市区町村名
- geometry: 境界ポリゴン（EPSG:4612 / JGD2011）

## テーブル: future_population_municipality

市区町村別の将来推計人口（2020〜2070年、5年ごと）。1kmメッシュ別将来推計人口を市区町村コード（SHICODE）で集計したもの。複数市区町村にまたがるメッシュの人口は該当市区町村へ均等按分して集計する。政令指定都市は区単位のコードで収録される。

- city_code: 市区町村コード（5桁。政令指定都市は区単位）
- prefecture_code: 都道府県コード（2桁）
- prefecture_name / county_name / city_name / ward_name: 都道府県名・郡名・市区町村名・行政区名（行政区名は政令指定都市のみ、他は NULL）
- population_2020 〜 population_2070: 推計年次別の総人口（人、2020〜2070年の5年ごと）
- growth_rate_2025_2035 / growth_rate_2025_2050: 人口増減率（%。2025年比）
- elderly_ratio_2025 / elderly_ratio_2050: 高齢化率（65歳以上人口の割合、%）

メッシュの SHICODE は令和2年国勢調査時点のコードのため、その後に再編された一部の自治体（浜松市の旧行政区など）や福島県浜通りの特別集計コード（07999）では名称が NULL になる。

## テーブル: future_population_mesh

1kmメッシュ単位の将来推計人口。地図ヒートマップ用。

- mesh_id: メッシュコード（基準地域メッシュ、1km四方）
- city_code: 市区町村コード（複数市区町村にまたがるメッシュは "_" 連結）
- population_2025 / population_2035 / population_2050: 推計年次別の総人口（人）
- growth_rate_2025_2050: 人口増減率（%。2025年比）
- elderly_ratio_2025 / elderly_ratio_2050: 高齢化率（%）
- geometry: メッシュポリゴン（EPSG:6668 / JGD2011）

## テーブル: railway_line

鉄道路線（路線名・運営会社・鉄道区分単位）のラインジオメトリ。N02（令和6年）の路線区間を路線単位に ST_Union_Agg で集約したもの。

- railway_class_code: 鉄道区分コード（N02_001。普通鉄道JR=11、普通鉄道=12、軌道=21 など）
- railway_class: 鉄道区分
- operator_type_code: 事業者種別コード（N02_002。JRの新幹線=1、JR在来線=2、公営鉄道=3、民営鉄道=4、第三セクター=5）
- operator_type: 事業者種別
- line_name: 路線名
- operator: 運営会社
- geometry: 路線ライン（EPSG:6668 / JGD2011）

## テーブル: station

駅の代表点（ポイント）。N02（令和6年）の駅データ。駅は元データでは軌道区間のラインで表現されるため、その重心を代表点とした。同一駅が複数路線に属する場合は路線ごとに行が分かれる。

- railway_class_code: 鉄道区分コード（N02_001）
- railway_class: 鉄道区分
- operator_type_code: 事業者種別コード（N02_002）
- operator_type: 事業者種別
- line_name: 路線名
- operator: 運営会社
- station_name: 駅名
- station_code: 駅コード（N02_005c。駅を一意に識別する番号）
- station_group_code: 駅グループコード（N02_005g。乗換可能な同一駅グループを束ねるコード）
- geometry: 駅ポイント（EPSG:6668 / JGD2011。軌道区間ラインの重心）

## テーブル: station_passenger

駅ごとの1日あたり乗降客数（2011〜2024年度）。S12（2024年度版）の駅別乗降客数データ。原典は 1 行に全年度を横持ちで持つが、1 行 = 駅 × 年度に正規化した。ジオメトリは station と同じく軌道区間ラインの重心を代表点とする。

- station_code: 駅コード（S12_001c。station テーブルの station_code と同じ体系）
- station_group_code: 駅グループコード（S12_001g。300m以内かつ同名の駅を束ねるコード）
- station_name: 駅名
- operator: 運営会社
- line_name: 路線名
- railway_class_code: 鉄道区分コード（S12_004）
- railway_class: 鉄道区分
- operator_type_code: 事業者種別コード（S12_005）
- operator_type: 事業者種別
- year: 年度（2011〜2024）
- passenger_count: 乗降客数（人/日。記載の無い年度は NULL）
- data_availability_code: データ有無コード（1=データ有、2=データなし、3=非公開、4=駅なし）
- data_availability: データ有無
- duplicate_code: 重複コード（1=当該路線駅に記載、2=他路線駅に記載、3=駅なし）
- duplicate_status: 重複区分
- note: 備考（原典資料の名称や注記）
- geometry: 駅ポイント（EPSG:6668 / JGD2011。軌道区間ラインの重心）

複数路線が乗り入れる駅は路線ごとに行が分かれ、乗降客数はそのうち 1 行にだけ記載される。駅としての合計は `station_group_code` で集約して出す。原典は記載の無い年度に 0 を入れているが、0 人ではなく「この行には記録が無い」の意味なので、当該路線駅に記載があり（重複コード 1）かつデータ有（データ有無コード 1）の年度以外は `passenger_count` を NULL にしている。理由は 2 つのコード列から読める。

北海道旅客鉄道・東日本旅客鉄道の無人駅は原典に情報が無く、九州旅客鉄道は乗降客数上位300駅以外が非公開のため、これらは値が入らない。廃止された駅も乗降客数側には残るので、`station_code` で station と結合すると数十行は結合先が無い。

## テーブル: bus_stop

バス停留所の位置（ポイント）。P11（第3.0版・令和4年度）のバス停留所データ。民間路線バス・公営路線バス・コミュニティバスが対象で、高速バス・デマンドバス・貸切バス・スクールバスは含まない。同一道路上にある同一事業者・同一名称の停留所は原典の時点で統合されている。

- prefecture_code: 都道府県コード（2桁）。配布ファイルの単位で、原典の属性ではなくファイル名に由来する
- stop_name: バス停名（P11_001）
- operator: 事業者名（P11_002。コミュニティバスは自治体名）
- bus_class_codes: バス区分コード（P11_004。当該停留所に停まる系統の区分コードを重複なく昇順で並べたもの。1=路線バス（民間）、2=路線バス（公営）、3=コミュニティバス、4=デマンドバス、5=その他）
- bus_classes: バス区分（複数ある場合は ／ 区切り）
- route_count: 系統数
- routes: バス系統（P11_003。系統番号・系統名をカンマ区切りで並べたもの）
- remarks: 備考（P11_005）
- geometry: バス停ポイント（EPSG:6668 / JGD2011）

原典は 1 つのバス停に紐づく系統を P11_003_01〜35 / P11_004_01〜35 の 35 組に分けて持ち、1 組の中でも系統をカンマ区切りで詰め込んでいる（24 件で次の組に送られる）。本データセットでは 35 組を順に連結して 1 つの系統リストに戻している。系統名と区分コードは同じ位置で対応する。

## テーブル: bus_route

バス路線の経路（ライン）。N07（令和4年度）のバスルートデータ。民間路線バス・公営路線バス・コミュニティバスが対象。

- operator: 事業者名（N07_001。コミュニティバスは自治体名）
- geometry: 経路ライン（EPSG:6668 / JGD2011）

原典が経路を細かい区間に分けて持つため 1 行 = 1 区間になる。事業者ごとに 1 本の経路として見るには `ST_Union_Agg` で集約する。令和4年度版の属性は事業者名と備考のみで、備考は全件が空のため収録していない。旧版（平成23年度）にあった系統名・平日／土曜／日祝の運行頻度は令和4年度版には無く、便数の分析には使えない。

## テーブル: medical_institution

医療機関の位置（ポイント）。P04（第3.0版・令和2年）の医療機関データ。全国の病院・診療所・歯科診療所の名称・所在地・診療科目・病床数・開設者分類を収録する。

- medical_class_code: 医療機関分類コード（P04_001。病院=1、診療所=2、歯科診療所=3）
- medical_class: 医療機関分類
- institution_name: 施設名称

### 通学区域データの注意点

小学校区・中学校区に共通する。

- 収録範囲は、提供元の利用条件一覧で利用条件が「オープンデータ公開」とされた市区町村に限られる。条件公開（21）・商用利用不可（16）・商用利用および再配布不可（9）・公開不可および作成不可の市区町村は収録しない。加えて、提供元が資料を収集できず区域を作成していない市区町村もある。全国の学区を網羅したデータではないので、学区の無い地域は「学区が無い」ではなく「収録していない」と読む。公開条件は小学校区と中学校区で別々に定められているため、収録される市区町村も両者で一致しない。
- 通学区域はおおよその範囲で空間的な誤差を含み、順次見直されるため最新の指定状況が反映されていない場合がある。公式な資料としては扱えないので、区域の詳細は各市区町村の教育委員会に確認する。
- 学校コードは原典で未設定の区域があり、「閉校」のようにコードでない値が入っている行もある。英字1桁 + 数字12桁の形式でない値は NULL にしている。

5. 医療機関データ（P04）はパイプライン実行時に全国版 GeoJSON を自動ダウンロードする。
6. 学校データ（P29）はパイプライン実行時に全国版 GeoJSON を自動ダウンロードする。
7. バス停留所データ（P11）・バスルートデータ（N07）はパイプライン実行時に全国版 zip を自動ダウンロードする。P11 は全国版 zip の中に都道府県別 zip が入れ子になっているため、47 都道府県分の GeoJSON を取り出す。
8. 洪水浸水想定区域データ（A31a）はパイプライン実行時に地域単位の zip を自動ダウンロードし、想定最大規模の GeoJSON を Parquet に変換する。
9. 都市地域土地利用細分メッシュデータ（L03-b-u）はパイプライン実行時に 1 次メッシュ単位の zip を自動ダウンロードし、GeoJSON を Parquet に変換する。
10. 福祉施設データ（P14）はパイプライン実行時に47都道府県分の GeoJSON を自動ダウンロードし統合する。
11. 用途地域データ（A29）はパイプライン実行時に都道府県単位の zip を自動ダウンロードし、オープンデータ公開可の市区町村の GeoJSON を Parquet に変換する。
12. 通学区域データ（A27 / A32）はパイプライン実行時に都道府県単位の zip を自動ダウンロードし、オープンデータ公開の市区町村の GeoJSON を Parquet に変換する。
13. 津波浸水想定（A40）はパイプライン実行時に都道府県 × 整備年度単位の zip を自動ダウンロードし、オープンデータ利用可の都道府県分を Parquet に変換する。
14. 土砂災害警戒区域（A33）はパイプライン実行時に都道府県単位の zip を自動ダウンロードし、オープンデータ利用可の都道府県分を Parquet に変換する。
15. `bash scripts/build.sh` でビルドする。

洪水浸水想定区域データ（A31a）の更新運用:

- 全国分のダウンロードは zip 合計 10GB 超と重いため、CI（GitHub Actions）ではスキップされる（`GITHUB_ACTIONS` 環境変数を検出して自動スキップ。`NLFTP_SKIP_FLOOD=1` で明示的にスキップ、`=0` で強制実行も可能）。CI のビルドでは flood タグのモデルが `--exclude` され、カタログ上の既存テーブルはそのまま維持される。
- 初回フルビルドと年次更新は手元で `bash scripts/build.sh` を実行する（`QUERIA_TOKEN` が要る。公開先は選ばない）。
- 変換済み Parquet（`data/flood/parquet/`）と処理済みマーカー（`data/flood/.done/`）が残っていれば該当分はスキップされるため、中断しても再実行で続きから処理できる。年次更新時はパイプラインの URL の版（A31a-25 等）を更新し、`data/flood/` を削除してから再実行する。
- 対象地域を絞る場合は `NLFTP_FLOOD_REGIONS`（カンマ区切り、例: `NLFTP_FLOOD_REGIONS=13,83`）を指定する。

都市地域土地利用細分メッシュデータ（L03-b-u）の更新運用:

- zip 合計 300MB 超・展開後の GeoJSON は 1 ファイルで 150MB を超えるため、1 ファイルずつ Parquet に変換して即座に削除する。変換済み Parquet（`data/landuse/parquet/`）が残っていれば該当メッシュはスキップされるため、中断しても再実行で続きから処理できる。
- 版を更新するときはパイプラインの URL の版（L03-b-u-21 等）と整備済み 1 次メッシュの一覧を更新し、`data/landuse/` を削除してから再実行する。
- 対象メッシュを絞る場合は `NLFTP_LANDUSE_MESHES`（カンマ区切り、例: `NLFTP_LANDUSE_MESHES=5339,5340`）を指定する。

用途地域データ（A29）の更新運用:

- 市区町村ごとの公開条件はパイプライン実行時に提供元の一覧（PDF）を取得して判定する。一覧の読み取り件数が想定を下回る場合はエラーで停止し、判定できない市区町村が zip に含まれる場合もエラーで停止する（判定できないデータを公開しないため）。
- 変換済み Parquet（`data/zoning/parquet/`）が残っていれば該当都道府県はスキップされる。年次更新時はパイプラインの URL の版（A29-19 等）を更新し、`data/zoning/` を削除してから再実行する。
- 対象都道府県を絞る場合は `NLFTP_ZONING_PREFECTURES`（カンマ区切り、例: `NLFTP_ZONING_PREFECTURES=13,14`）を指定する。

通学区域データ（A27 / A32）の更新運用:

- 市区町村ごとの公開条件・利用条件はパイプライン実行時に提供元の一覧（Excel）を取得して判定する。小学校区と中学校区は同じ市区町村でも利用条件が異なることがあるため、列を分けて見る。一覧の列の並びが変わった場合・読み取り件数が想定を下回る場合はエラーで停止し、判定できない市区町村が zip に含まれる場合もエラーで停止する（判定できないデータを公開しないため）。
- 変換済み Parquet（`data/school_district/elementary/`・`data/school_district/junior_high/`）が残っていれば該当都道府県はスキップされる。年次更新時はパイプラインの版（A27-23 / A32-23 等）と一覧の URL を更新し、`data/school_district/` を削除してから再実行する。
- 対象都道府県を絞る場合は `NLFTP_SCHOOL_DISTRICT_PREFECTURES`（カンマ区切り、例: `NLFTP_SCHOOL_DISTRICT_PREFECTURES=13,14`）を指定する。

津波浸水想定（A40）の更新運用:

- 都道府県ごとの使用許諾条件と配布ファイルの一覧は、パイプライン実行時に配布ページを取得して読み取る。オープンデータ利用可と読み取れた都道府県が想定を下回る場合・一覧のファイル数が想定を下回る場合はエラーで停止する（判定できないデータを公開しないため）。読み取った区分は `hazard.raw_tsunami_license` に残り、公開テーブルに区分1以外が混ざっていないことを dbt テストで確かめる。
- 新しい整備年度が配布ページに載れば次回のビルドで自動的に取り込まれる。年度の指定はパイプラインに持たせていない。
- zip には GeoJSON が入るものと入らないものがある。GeoJSON が無い年度はシェープファイルから読む。属性の .dbf は CP932 で DuckDB がそのまま読めないため、幾何を .shp から・属性を自前でデコードして読み、レコード順で突き合わせる（件数が食い違えばエラーで停止する）。
- 変換済み Parquet（`data/tsunami/parquet/`）が残っていれば該当ファイルはスキップされる。取り直すときは `data/tsunami/` を削除してから再実行する。
- 対象都道府県を絞る場合は `NLFTP_TSUNAMI_PREFECTURES`（カンマ区切り、例: `NLFTP_TSUNAMI_PREFECTURES=06,28`）を指定する。

土砂災害警戒区域（A33）の更新運用:

- 都道府県ごとの使用許諾条件は、パイプライン実行時に配布ページを取得して読み取る。オープンデータ利用可と読み取れた都道府県が想定を下回る場合・いずれの区分にも現れない都道府県がある場合・ダウンロード一覧のファイル数が47と一致しない場合はエラーで停止する（判定できないデータを公開しないため）。読み取った区分は `hazard.raw_landslide_license` に残り、公開テーブルに区分1以外が混ざっていないことを dbt テストで確かめる。
- 配布は GeoJSON・シェープファイル・GML の3形式だが、シェープファイルの .dbf は CP932 で DuckDB がそのまま読めないため GeoJSON を使う。区域は面と線の両方で整備され zip に GeoJSON が2つ入ることがあるので、面（`...Polygon.geojson`）だけを読む。
- 変換済み Parquet（`data/landslide/parquet/`）が残っていれば該当都道府県はスキップされる。年次更新時はパイプラインの版（A33-25 等）とページの URL を更新し、`data/landslide/` を削除してから再実行する。
- 対象都道府県を絞る場合は `NLFTP_LANDSLIDE_PREFECTURES`（カンマ区切り、例: `NLFTP_LANDSLIDE_PREFECTURES=13,47`）を指定する。
